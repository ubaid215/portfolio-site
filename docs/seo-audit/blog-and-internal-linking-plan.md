# Blog and internal linking plan

**Prepared:** 17 October 2026
**Constraint:** one solo developer, 4–6 hours per day available for business development, near-zero budget, and a need for income soon. This plan assumes content is a **supporting** channel for outreach, not a traffic strategy that pays this quarter.

All query hypotheses are labelled as hypotheses. **No search volume, difficulty, CPC or competition score is claimed.**

---

## Principle

Publish only what you can write from first-hand work.

You have five delivered systems and one product. That is enough for roughly eight genuinely original articles. It is not enough for a content operation. Two useful articles per month, each linked to a service and a case study, is the entire plan. Nothing is generated at scale, no city pages, no listicles.

**Success is not traffic.** For the first 90 days the useful outcomes are:
1. An article gives an outreach email something specific to reference.
2. A prospect reads one and replies.
3. Search Console starts showing impressions for queries you actually targeted.

### Target graph

```
                    ┌──────────────┐
                    │      /       │
                    └──────┬───────┘
        ┌──────────────────┼───────────────────┐
        ▼                  ▼                   ▼
   /services         /work (hub)         /insights (hub)
        │                  │                   │
   ┌────┴────┐        ┌────┴────┐         ┌────┴────┐
   ▼    ▼    ▼        ▼         ▼         ▼         ▼
 svc1  svc2  hvac   case1 ... case5     art1 ...  art8
   │     │      │      │                    │
   └─────┴──────┴──────┴────────────────────┘
        (each service ↔ its 1–2 best case studies)
        (each article → exactly 1 service + 1 case study)
```

### Rules

1. **Every case study links to one service page** in prose, near the outcome — not in a sidebar. Anchor text should describe the service ("see how I build lead-handling workflows"), never "click here".
2. **Every service page links to 1–2 case studies and 1 article.** More looks like a link farm; fewer wastes the authority.
3. **Every article links to exactly one service and one case study.** A second service link is allowed only if the article genuinely compares them.
4. **Breadcrumbs on all nested routes:** `Home / Insights / Title` and `Home / Work / Project`.
5. **Hub pages (`/work`, `/insights`, `/services`) must contain real prose**, not just cards. `/work` currently has 376 words total; that is the first thing to fix.
6. **No link blocks in footers** beyond the existing navigation. No "related posts" grid of twelve.
7. **One canonical URL per topic.** When `/services/hvac-lead-follow-up` exists, `/services#ai-automation` must not also try to own that intent.

## Measurement

Track per article, monthly, in a simple sheet:

| Column | Source |
|---|---|
| Impressions | Search Console → Pages |
| Clicks | Search Console |
| Average position | Search Console |
| Queries it appears for | Search Console → Queries filtered by page |
| Enquiries that mention it | Your lead log, asked on the call |
| Outreach emails that cite it | Your outreach log |

Do not install scroll-depth or heatmap tools for this. The only question that matters is whether an article produced a conversation.
